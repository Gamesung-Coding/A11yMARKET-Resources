본 문서는 ‘사용자 맞춤형 접근성 프로필 기반 상품 중계 쇼핑몰’ 프로젝트의 MVP 개발을 위한 사용자 시나리오 및 인수 기준을 정의한다.

## 1. 공통 및 회원 관리

### 시나리오 1.1: 접근성 프로필 설정

사용자는 플랫폼에 처음 방문하여 상단 메뉴 또는 마이페이지의 접근성 프로필 항목에서 자신에게 최적화된 UI 환경을 선택하고 저장할 수 있다.

| Acceptance Criteria                                                                                                                                                            | 관련 페르소나 및 요구사항  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| **Given** 사용자가 접근성 프로필 설정에 진입<br>**When** 큰 클씨 모드를 선택하면<br>**Then** 사이드 내 모든 텍스트가 즉시 1.5rem 이상으로 커진다.                              | \[김복순/이정호: 큰 글씨\] |
| **Given** 사용자가 접근성 프로필 설정에서 고대비 모드를 선택<br>**When** 페이지를 다시 로드할 때<br>**Then** 페이지가 즉시 검은색 배경과 흰색 텍스트이 고대비 테마로 전환된다. | \[이정호: 고대비\]         |
| **Given** 사용자가 플랫폼에 다시 방문<br>**When** 페이지가 로드될 때<br>**Then** 로컬 스토리지/회원 정보를 바탕으로 접근성 프로필을 설정한다.                                  | \[공통\]                   |

### 시나리오 1.2: 회원 가입 및 로그인

사용자는 플랫폼에 방문하여 회원가입과 로그인을 진행할 수 있다.

시스템은 해당 사용자의 프로필을 확인하고, 맞춤형 UI 환경을 체크한다.

| Acceptance Criteria                                                                                                                                           | 관련 페르소나 및 요구사항 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 사용자가 회원가입 페이지에 접근했을 때<br>**When** Tab 키를 누르면<br>**Then** 모든 입력 필드와 버튼에 논리적인 순서로 초점(focus)이 이동해야 한다. | \[공통\]                  |
| **Given** 사용자가 로그인 한 경우<br>**When** 페이지에 접근성 프로필 설정이 되어 있지 않으면<br>**Then** 회원이 설정한 접근성 프로필이 즉시 적용된다.         | \[공통\]                  |

## 2. 상품 탐색 및 조회

### 시나리오 2.1: 상품 검색 및 목록 탐색

사용자가 메인 페이지의 검색창을 이용해 원하는 상품을 검색한다. 검색 결과 페이지로 이동하면, 시스템은 검색된 상품의 총개수를 명확하게 안내한다. 사용자는 필터나 정렬 기능을 사용하여 원하는 상품 목록을 다시 추린다.

### 시나리오 2.2: 상품 상세 정보 확인

사용자가 상품 목록에서 특정 상품을 선택하여 상세 페이지로 진입하면, 페이지 상단에는 복잡한 상품 설명 대신 AI가 생성한 '핵심 요약 정보'가 먼저 노출된다.

사용자는 이 요약 정보를 '음성으로 듣기(TTS)' 버튼을 통해 들을 수 있으며, 상품 이미지는 스크린 리더 사용자를 위해 명확한 '대체 텍스트'를 제공한다.

| Acceptance Criteria                                                                                                                                                                   | 관련 페르소나 및 요구사항 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 상품 상세 페이지에 진입했을 때<br>**When** 상품 설명 영역을 보면<br>**Then** 복잡한 설명 상단에 AI 요약을 통해 쉬운 용어로 작성된 요약문이 접근성 프로필에 맞추어 표시된다. | 공통                      |
| **Given** AI 요약문 옆에 있는 스피커 아이콘이 로드된 후<br>**When** 사용자가 아이콘을 누르면<br>**Then** TTS를 통해 해당 요약문을 음성으로 재생한다.                                  |                           |
| **Given** Tab 키로 상품 이미지를 탐색할 때<br>**When** 상품 이미지로 초점이 이동하면<br>**Then** 스크린 리더는 사진의 대체 텍스트(alt)를 읽는다.                                      |                           |
| **Given** 상품 상세 페이지를 볼 때<br>**When** 해당 상품이 인증 판매자의 상품이면<br>**Then** 판매자의 이름 옆에 플랫폼 인증 마크가 명확히 표기된다.                                  |                           |
| **Given** 장바구니 담기 버튼으로 초점을 이동한 경우<br>**When** 스크린 리더가 버튼을 읽으면<br>**Then** 명확한 라벨을 읽어줘야 한다.                                                  |                           |

## 3. 주문 및 결제

### 시나리오 3.1: 장바구니 관리 및 결제 이동

사용자가 `장바구니 담기`를 누르면, 시스템은 즉각적인 피드백을 제공한다.

사용자가 장바구니 페이지로 이동하면, 현재 담긴 상품 내역과 총 결제 금액을 명확히 인지할 수 있으며, UI의 요소는 명확히 노출되어야 한다.

| Acceptance Criteria                                                                                                                                                        | 관련 페르소나 및 요구사항 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 장바구니 담기를 활성화한 경우<br>**When** 상품이 장바구니에 성공적으로 추가되면<br>**Then** 상품이 장바구니에 담겼다는 메시지를 ARIA Live로 안내한다.            |                           |
| **Given** 장바구니 페이지에 진입한 경우<br>**When** 페이지가 로드되면,<br>**Then** 스크린 리더는 장바구나 핵심 요약 점보를 먼저 안내한다.                                  |                           |
| **Given** 단순 UI 모드에서 장바구니에 접근한 경우<br>**When** 결제를 진행할 때<br>**Then** 관련 없거나 광고성 항목은 숨김 또는 축소처리 되고, 결제 버튼이 명확히 표시된다. |                           |

### 시나리오 3.2: 결제 프로세스

사용자는 결제하기 버튼을 눌러 결제 페이지로 이동한다. 간편 결제를 제공하고, 키보드 조작만으로 결제 수단을 선택할 수 있으며, 결제 대행(PG)사 팝업이 뜨면 초점이 자동으로 팝업 내부로 이동하여 결제를 계속 진행합니다.

| Acceptance Criteria                                                                                                                                                                                                        | 관련 페르소나 및 요구사항 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 결제 페이지에 진입했을 때<br>**When** 결제 수단 선택 시<br>**Then** 간편 결제 버튼을 제일 상단에 띄워 노출한다.                                                                                                  |                           |
| **Given** 결제 페이지에서 키보드로 간편 결제 수단을 선택하고 결제하기를 실행했을 때<br>**When** 결제 대행사 팝업이 뜨면<br>**Then** 키보드 초점은 즉시 PG사 팝업 내부로 이동한다.<br>팝업이 닫히기 전까지 초점이 유지된다. |                           |

### 시나리오 3.3: 주문 조회 및 취소

결제를 완료한 사용자는 마이페이지의 주문 내역 에서 방금 주문한 건의 상태를 확인한다. 만약 주문을 잘못하여 취소해야 할 경우 배송 시작 전 상태라면 주문 취소 버튼을 찾아 요청 할 수 있다.

| Acceptance Criteria                                                                                                                                                            | 관련 페르소나 및 요구사항 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| **Given** 마이페이지의 주문 내역에 접근했을 때<br>**When** 방금 주문한 내역을 키보드로 탐색하면<br>**Then** 상품 이름과 상태를 명확히 읽어준다.                                |                           |
| **Given** 배송 시작 전 상태의 주문을 확인하기 위해 주문 내역에 접근하면<br>**When** 해당 주문 내역을 보면<br>**Then** 주문 취소와 배송 조회가 각각 강조되어 명확히 렌더링된다. |                           |

## 4. 플랫폼 신뢰 시스템

### 시나리오 4.1: 구매 확정 및 정산

구매자가 상품을 배송 받은 후 마이페이지에서 구매 확정을 누른다. 확정 시 관리자는 해당 거리를 완료 처리하고, 판매자의 정산 시스템의 정산 예정 현황에 편입된다.

| Acceptance Criteria                                                                                                                                                                    | 관련 페르소나 및 요구사항 |
| :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------ |
| **Given** 구매자가 배송 완료 상태의 주문을 주문 내역에서 확인할 때<br>**When** 구매 확정 버튼을 클릭하고 확인 팝업에서 예를 클릭하면<br>**Then** 주문의 상태는 구매 확정으로 변경된다. |                           |
| **Given** 구매자가 구매 확정을 클릭한 뒤,<br>**When** 판매자가 판매 현황 페이지에 방문하면<br>**Then** 판매 현황에 정산 예정 목록으로 편입되어 보여진다.                               |                           |
| **Given** 관리자가 관리자 페이지의 주문 관리에서 해당 주문 건을 조회할 때,<br>**When** 상태를 변경하면<br>**Then** 해당 상태로 표시되며, 관련 정산 캐치 작업이 트리거 된다.            |                           |

## 5. 판매자 기능

### 시나리오 5.1: 판매자 가입 및 승인

신규 판매자가 판매자 가입 신청 페이지에서 최소한의 정보와 사업자 등록증 사진 파일만 업로드하여 간편하게 입점을 신청한다. 관리자는 관리자 페이지에서 이 신청을 검토하고, 확인 후 승인처리 하여 신규 판매자 등급을 부여한다.

| Acceptance Criteria                                                                                                                                                                                                        | 관련 페르소나 및 요구사항 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 판매자가 판매자 가입 신청 페이지에 접근했을 때,<br>**When** 필수 정보와 사용자 등록증을 입력/업로드하고 '신청'을 누르면,<br>**Then** 승인 대기 상태를 안내하는 페이지로 이동한다.                                |                           |
| **Given** 관리자가 관리자 페이지의 판매자 관리 메뉴에 접근했을 때,<br>**When** 판매자의 승인 대기 건을 클릭하여 서류를 확인하고 '승인' 버튼을 누르면,<br>**Then** 판매자의 계정 상태가 신규 판매자 등급으로 즉시 변경된다. |                           |

### 시나리오 5.2: 판매자 대시보드 및 주문 처리

판매자가 판매자 센터에 로그인하면, 광고나 부가기능 대신 '오늘 할 일'이 명확히 보이는 단순한 대시보드를 마주합니다. 대시보드에서 '신규 주문' 건수를 확인하고, 클릭하여 주문 상세 내역을 확인한 뒤 '배송 처리'를 완료합니다.

| Acceptance Criteria                                                                                                                                                                                              | 관련 페르소나 및 요구사항 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Given** 판매자가 판매자 센터에 로그인했을 때,<br>**When** 메인 대시보드가 렌더링되면<br>**Then** 신규 주문, 배송 준비 상태 등 가장 중요한 정보가 큰 아이콘과 숫자로 표시된다.                                  |                           |
| **Given** 판매자가 대시보드에서 신규 주문 건을 클릭했을 때,<br>**When** 배송 처리 버튼을 누르고 송장 번호를 입력하면,<br>**Then** 해당 주문의 상태가 배송 중으로 변경되고, 구매자에게 배송 시작 알림이 발송된다. |                           |
